## 1 · DEFECT UNDER CORRECTION

**NV01-D01** — bounded to the governing file `src/lib/marketData/sessionSymbolStore.ts`, field `LocalStatsClearResult.preservedEvidence`.

V1.0 proposed that `LocalStatsClearResult.preservedEvidence` name the tuple:

```
SESSION_NECTAR_CHANNELS
BROWSER_COVERAGE_CONTINUITY
SERVER_OPERATIONAL_COVERAGE
RIGHTS_EVIDENCE
```

as runtime evidence returned by `clearLocalStats`.

Sentinel's ruling (adopted verbatim): `sessionSymbolStore` can prove only that its operation targets its own `Map` and its own `wm:session-symbol-store` key. It cannot prove that external evidence exists, is valid, or remains available. Returning this tuple would promote a static non-mutation boundary into fabricated evidence and exceed the owner's authority.

## 2 · CORRECTIONS (V1.0 → V1.0.1)

The following six corrections are the entirety of the V1.0.1 delta.

### 2.1 · Remove the overreaching field

Remove `LocalStatsClearResult.preservedEvidence` from `src/lib/marketData/sessionSymbolStore.ts` in its entirety. It does not exist in V1.0.1.

### 2.2 · Optional scope marker

If a typed scope marker is required by any downstream consumer, `LocalStatsClearResult` may carry **only** the following literal field, exactly as specified:

```ts
readonly affectedScope: "BROWSER_LOCAL_SESSION_SYMBOL_STATS_ONLY";
```

No other value is permitted for `affectedScope`. No union widening. No enum. No provider identifiers. No coverage keys. No receipt identifiers. No rights identifiers.

### 2.3 · Confirmation disclosure text

The user-facing confirmation disclosure text (previously described V1.0 language, whatever it was) becomes exactly:

> "This removes browser-local performance stats only. It does not request changes to coverage continuity, server coverage receipts, rights evidence, or other Market Memory evidence. Their availability and state are reported separately."

Rendered verbatim. No paraphrase. No abbreviation. Line-break handling per the UI primitive; the character sequence between the opening quote and the closing period must match byte-for-byte.

### 2.4 · R13 fixture preserved as fixture

R13 remains a **fixture** proving the separately-owned browser coverage-continuity localStorage key is byte-identical before and after the clear operation. V1.0.1 keeps this fixture and its acceptance semantics unchanged.

R13 does **not** produce runtime evidence from `sessionSymbolStore` and does **not** contribute a value to `LocalStatsClearResult`. Its role is external-key non-mutation proof, run under the test harness, not shipped as a runtime claim.

### 2.5 · Compile / static assertion

V1.0.1 adds a compile / static assertion (implementation deferred to the authorized implementation baton) that:

`LocalStatsClearResult` cannot carry any of the following fields:

- coverage identifiers (any name matching `/coverage/i` beyond the fixed literal `affectedScope`),
- receipt identifiers,
- rights identifiers,
- C03 acknowledgement fields,
- provider identifiers,
- any other external-evidence field.

The exact form of the assertion (structural exact-type check, `Exact<>` helper, or equivalent) is implementation choice for the authorized implementation baton. Its acceptance is: adding any forbidden field to `LocalStatsClearResult` fails typecheck at authoring time.

If V1.0 already carried a compile assertion in this position, this new assertion **replaces** it in place. No manifest expansion.

### 2.6 · Preserve every other binding

Every other V1.0 term — the four-path manifest verbatim, R01–R22 / C01–C08 totals verbatim, six dirty-file hashes verbatim, exclusions verbatim, evidence gates verbatim, rollback verbatim, async boundary + ordering + terminal-state behavior verbatim, zero-network rule, mobile-nav and PR exclusions — is carried into V1.0.1 unchanged.
